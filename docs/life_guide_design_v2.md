# 人生指南 V1 设计稿

## 1. 产品定位

人生指南不是日记摘要合集，也不是 AI 对用户的人格分析。

它保存的是：用户从真实经历和深入思考中，亲自确认并愿意带往未来的认识。

- 日记回答“我经历了什么”。
- 深度对话回答“我是怎样一步步想明白的”。
- 人生碎片回答“这件事让我更理解了什么”。
- 人生指南把多个人生碎片组织成一套可以持续修订的个人经验体系。

核心原则：AI 负责发现、提问和整理，用户拥有最终解释权。

## 2. V1 最小闭环

1. 用户在日记详情页点击“提炼为人生碎片”。
2. 用户选择本次提炼的材料：
   - 当前日记正文（必选）。
   - 当前日记的 AI 对话（可选，默认不选）。
   - 当前日记的 AI 悄悄话（可选，默认不选）。
3. AI 生成一份可编辑草稿。
4. 用户逐项修改并确认。
5. 草稿保存为人生碎片，同时保留来源日记 ID。
6. 用户可以从人生指南阅读、搜索、修订或删除这篇内容。

任何 AI 结果都不能绕过确认直接进入人生指南。

## 3. 信息架构

### 3.1 人生指南首页

入口放在“回忆”页，并作为高优先级卡片呈现。

页面顺序：

1. 我的绳子
2. 最近形成的人生碎片
3. 按主题浏览
4. 待继续思考的草稿

“我的绳子”只展示用户主动标记的内容，不由 AI 自动决定。

### 3.2 主题

V1 使用固定主题加自定义标签：

- 关于我是谁
- 失败与不确定
- 关系、孤独与爱
- 学业、工作与选择
- 我真正看重的东西
- 曾经帮助过我的方法
- 让我愿意继续生活的事
- 写给未来的自己

一篇人生碎片只能有一个主主题，可以有多个自定义标签。

### 3.3 人生碎片详情

阅读顺序：

1. 标题
2. 核心认识
3. 它来自什么经历
4. 支撑这个认识的真实证据
5. 未来什么时候需要重新读到它
6. 写给未来自己的话
7. 来源日记
8. 创建时间与最后修订时间

详情页支持编辑、标记为“我的绳子”、查看来源日记、删除。

## 4. 人生碎片数据模型

```text
LifeFragment
  id: String
  title: String
  coreInsight: String
  context: String
  evidence: String
  futureUse: String
  messageToFutureSelf: String
  theme: LifeFragmentTheme
  tags: List<String>
  sourceDiaryIds: List<String>
  isRope: bool
  status: draft | confirmed
  createdAt: DateTime
  updatedAt: DateTime
```

V1 不保存不可解释的“人格分数”“心理诊断”或 AI 推断标签。

## 5. 提炼草稿页面

页面标题：“这段经历，留下了什么？”

### 5.1 生成前

展示本次材料范围，并明确：

> AI 会帮助整理，但只有你确认的内容才会进入人生指南。

用户可以取消选择 AI 对话和 AI 悄悄话，避免把不希望长期保存的对话带入指南。

### 5.2 生成后

所有字段都是普通可编辑输入框，不使用不可修改的 AI 卡片。

提供三个操作：

- 保存为草稿
- 确认并收进人生指南
- 放弃

“标记为我的绳子”默认关闭，必须由用户主动开启。

## 6. AI 提炼规则

AI 必须：

- 只依据用户选择的材料。
- 区分事件事实、用户原话和归纳结果。
- 优先保留用户有辨识度的表达。
- 找不到明确领悟时直接说明“这次材料更像经历记录，暂时不必提炼”。
- 允许结论保持矛盾和不确定，不强行制造积极意义。
- 输出结构化草稿，不直接保存。

AI 禁止：

- 根据单篇日记定义用户人格。
- 虚构童年、关系、创伤或动机。
- 把痛苦自动包装成成长。
- 使用“你一直都是”“你本质上是”等绝对判断。
- 模仿心理医生作诊断。
- 为了文采改变事实。

## 7. 与《写给未来自己的绳子》的对应示例

```text
标题：写给未来自己的绳子
主题：失败与不确定
核心认识：
  我不是因为永远成功，所以相信自己；而是因为我见过自己最狼狈的时候，
  依然没有放弃自己。
经历背景：
  面对保研结果的不确定和机会失落，我重新读到了高中低谷时期留下的日记。
真实证据：
  高中时期的我曾在成绩受挫和孤立无援中写下“永远心怀希望，永远期待朝霞”，
  并最终走过了那段生活。
未来用途：
  当我再次因为失败怀疑自己，或者觉得已经辜负过去的自己时重新阅读。
给未来自己的话：
  过去的我没有辜负现在的我。现在的我，也没有辜负过去的我。
标记：我的绳子
```

这只是结构映射示例。正式导入前仍需用户确认原文与字段内容。

## 8. 隐私与数据策略

- 人生碎片默认只保存在本地数据库。
- 来源日记只保存 ID，不复制整篇日记正文。
- 删除来源日记时，不自动删除已经确认的人生碎片，但显示“原日记已删除”。
- 删除人生碎片不影响来源日记。
- 导出备份时将人生碎片包含在用户主动创建的备份中。
- AI 提炼前明确展示本次将发送的材料范围。

## 9. V1 暂不实现

- 自动扫描全部历史日记并批量生成。
- AI 自动判断“我的绳子”。
- 跨文章生成固定人格画像。
- 对用户进行心理健康评分。
- 自动合并观点相似的文章。
- 未确认就主动改写既有文章。

这些能力如果以后加入，也必须建立在来源可追溯、用户确认和可撤销之上。

## 10. 后续演进

V2 可以支持：

- 为同一篇人生文章追加新的来源日记。
- 查看一条认识随时间发生的修订历史。
- “过去的我如何理解 / 现在的我如何理解”对照。
- 在低谷时只打开“我的绳子”。
- 从多篇已确认碎片中生成“关于我是谁”的阶段性草稿。

阶段性草稿仍然只是邀请用户思考，不是 AI 对用户的最终定义。
